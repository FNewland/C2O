# OER edit specification — "Concurrent Spacecraft Design" (SpaceCDF textbook)

Binding for every editing agent. Source of truth for numbering, notation, cross-references and cuts. Read `oer_inventory.md` for line-level evidence.

## 0. Goal
Convert `docs/course/facilitator_book_expanded.md` into a standalone Open Educational Resource: no course, workbook, worksheet, lecture, session, facilitator, institution or timetable references; one clean treatment of each topic; figures placed where they are discussed; end-of-chapter problems instead of tool exercises; CC BY 4.0; neutral SpaceCDF branding.

## 1. Work layout
- Source stays a single file during editing: `docs/course/facilitator_book_expanded.md` is **not** edited in place. Agents write to **`docs/oer/book.md`** split into per-chapter files `docs/oer/chapters/NN_<slug>.md` (NN = 00 front matter, 01–20 chapters, 21 position reference, 22 derivations, 23 tool appendix, 24 back matter). The build concatenates in numeric order.
- Each agent owns specific chapter files and never edits another agent's file. Cross-chapter fixes that require touching someone else's chapter are written as a note in `docs/oer/XREF_NOTES.md` (append-only) for the integrator.
- Images: references are `../assets/figures/<name>.png` (relative to `docs/oer/`). Never `../../`.

- "Discussion point" and inline "Exercise" blocks → either become a numbered Problem (move to Problems, keep the substance) or a short `**Think about it.**` reflective prompt inline if it is purely reflective. No worksheet references survive.
- "Tool Exercise" / "SpaceCDF Exercise" / "Worksheet N.N Tasks" sections → converted into Problems (the engineering content, not the click path). Problems may say "using a concurrent-design tool or a spreadsheet, …" but never name SpaceCDF or its tabs.
- "Session Summary" → "Summary". "By the end of this session, participants will…" → "By the end of this chapter, you will…".
- Remove "Prerequisites: Session X.Y" lines; where the dependency is real, write one sentence in the opening paragraph ("This chapter builds on the V-model of Chapter 1.").
- In-text forward/back references by session number → "Chapter N, §N.k".
- References section: title `## References`; one style — numbered list, author/title/year, URL on the same line.

## 5. Notation and consistency (apply everywhere)
- Constants: R_E = 6378.137 km, μ = 398 600.44 km³/s², J₂ = 1.0826 × 10⁻³, g₀ = 9.80665 m/s², k = −228.6 dBW/K/Hz. Chapter 7 worked numbers re-computed with R_E = 6378.137 (period at 450 km ≈ 93.6 min — check the Part III V.2 number and use the same).
- Power sizing: canonical form is Chapter 9's. `P_SA,EOL = (P_sun·t_sun/η_sun + P_ecl·t_ecl/η_ecl)/t_sun`, `A_SA = P_BOL/(η_cell·S·cos θ·f_pack·f_cover)`, `P_BOL = P_EOL/(L_d·L_T)`, `E_bat = P_ecl·t_ecl/(DoD·η_dis)`; θ = Sun incidence angle on the array (state that for a nadir-pointed body panel θ relates to β). Part III V.11 derives *this* form and notes the f_ecl/f_sun equivalent. Delete the equations from Ch 4 §ConOps (point to Ch 9) and the Part II Power entry (cross-ref).
- Link budget: canonical `C/N₀ = EIRP − FSPL − L_atm − L_point − L_pol − L_rx + G/T − k` (Ch 11). Part II Comms and Part III V.7 use the same symbols.
- Eclipse fraction: β-angle form in Ch 7 and V.5 (`f_ecl = (1/π)·arccos(√(h²+2R_E h)/((R_E+h)·cos β))` for |β|<β*). Chapter 7 presents the β = 0 special case as a corollary.
- Verification methods: **A/T/I/R** (Analysis, Test, Inspection, Review of design) + D for Demonstration where ECSS lists it; spell it "ATIR(D)". Replace TAID/ATID/IADT everywhere.
- Interface types: one table (Ch 8 §8.3): Mechanical, Electrical/Power, Thermal, Data, RF, Optical, Software — letter codes M/E/T/D/R/O/S. Ch 15 uses the same codes.
- ECSS margin schedule: one table (Ch 8 §8.4) from ECSS-E-ST-10-02C/ECSS-E-ST-32: Phase 0/A 20 %, B 15 %, C 10 %, D 5 % *system-level mass margin on top of equipment maturity margins* (state the two-level structure). Part II and others cross-ref it; do not restate numbers.
- Operational-mode power table: one table (Ch 18), explicitly "3U EO CubeSat, UniSat-1": Safe 2 W, Nominal/standby 4 W, Imaging 8 W, Downlink 10 W (consistent with the UniSat-1 running example values used in Ch 9). Ch 4 keeps only the *concept* of modes with a 3-row illustrative table using the same numbers.
- Unicode: use — ≤ ≥ ± ° µ Δ throughout (replace ASCII `--`, `<=`, `>=`, `+/-`, `deg`, `?V`). LaTeX `$…$` for inline math, `$$…$$` for display, in all chapters (Ch 13–19 currently have none — typeset their formulas: CER `C = a·M^b`, learning curve `T_n = T_1·n^{log_2 L}`, reliability `R(t)=e^{−λt}`, series/parallel, P50/P80).
- UK spelling. Vendor names allowed with "representative example, not an endorsement" once per chapter; prices as "indicative (2026)".
- **Running examples — RULING (supersedes earlier wording):** the book has TWO running examples, as in the source: the **3U Earth-observation CubeSat** (the primary worked example in Ch 4–18 power/AOCS/link/structure chapters; call it "the 3U EO CubeSat" or, where a name is needed in tables, **"EOSat-3U"**) and **UniSat-1**, the **1U** MEMS-magnetometer demonstrator introduced in Ch 1 §1.7 as the simpler second example. Never label 3U numbers as UniSat-1. Ch 18's mode table is for the 3U EO CubeSat (Safe 2 W, Nominal 4 W, Imaging 8 W, Downlink 10 W) and must say so.
