How to use

design-system.csscomponents.jsstate.js

Every console page starts with these two lines.

<link rel="stylesheet" href="/static/shared/design-system.css">
<script type="module">
import { renderValue, renderGauge, renderButton,
         armButton, setDisabled } from "/static/shared/components.js";
import { linkState, modeState } from "/static/shared/state.js";
</script>
  1. Use tokens such as var(--tx) or var(--accent), never a hex value.
  2. One modifier per state: is-disabled, is-armed, is-active, is-stale, is-nodata, is-caution, is-alarm.
  3. Disable with a reason: setDisabled(el, reason). The control stays focusable and the reason shows on hover and on focus.
  4. Critical commands go through armButton(): the first press arms, the second executes within 5 s.
  5. Never print a dash for a value. Stale keeps the last value with its age; never received says “no data”.

In context: power during a pass

A subsystem view built only from the shared components. At rest it is grey; the one amber line is the only thing asking for attention.

States

.is-disabled.is-armed.is-active.is-stale.is-nodata.is-alarm

Every control and value is in exactly one of these states. Hover or tab to a disabled control to read why it is disabled.

Buttons

renderButton()armButton()setDisabled().ds-btn

Default buttons are grey outlines. The raised button is the one main action of a panel. Amber stripes mark a critical command, which always takes two presses.

Values

renderParam()renderValue()renderAge()renderNoData()

The parameter triad: name and identifier, the value with its unit, and a scale with the limit bands drawn under it. Hover the scale to read the limits.

Gauges and trends

renderGauge()renderDeviationBar()renderSparkline()

The compact readout for overviews: picture first, exact value beside it. The fill stays grey until the value leaves its limits.

Tables

The alphanumeric display, one row per state. Numbers are right-aligned in tabular figures.
